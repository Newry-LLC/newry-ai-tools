# Summary formats

Derived outputs, offered after the transcript is approved in Phase 6. The user picks any combination.

Rules that apply to all of them:

- Build from the **approved** transcript, never a draft. A summary made from an unresolved transcript can carry a transcription error into a client deliverable.
- Every quotation is exact, with speaker and `[MM:SS]`. If you need to trim a quote, use an ellipsis; never paraphrase inside quotation marks.
- If a finding rests on text that is still flagged, say so. A finding built on unresolved audio is a finding with a caveat.
- Default output is Word (`.docx`) to match the transcript. Offer Markdown if the user wants to paste it somewhere.
- Deliver as a separate file. Don't append summaries to the transcript — the transcript's value is that it is only the transcript.

---

## Executive summary

One page. For someone who will not read the transcript.

```
# [Interviewee name, title, company] — [date]

**Why we spoke to them:** [1–2 sentences: their relevance to the project question]

**What matters most:** [3–5 bullets. Findings, not topics. "Qualification cycles run
18–24 months, which is the real barrier to entry" — not "discussed qualification."]

**Notable quotes:** [1–3, with timestamps]

**Implications for the project:** [2–3 bullets tying findings to the project question]

**Open questions / follow-ups:** [what this interview didn't answer]
```

The test of a good one: a partner reads it and knows whether they need the transcript. Write findings with their substance intact — "discussed pricing" tells the reader nothing.

## Key quotes

Deck-ready pull quotes. Aim for 8–15 from an hour-long interview; more than that and you're transcribing again.

```
## [Theme]

> "[Exact quote]"
> — [Name], [Title], [Company] · [MM:SS]

**Context:** [one line: what was asked, what prompted this]
**Why it matters:** [one line: what this supports or challenges]
```

Select for quotes that carry an argument — a specific number, a strong causal claim, a surprising position, or vivid phrasing a client will remember. Skip anything that only restates the obvious. Group by theme, not chronology, since that's how they'll be used.

Keep hedges in: "I *think* it's around 40%" is a different claim from "it's 40%," and stripping the hedge misrepresents the speaker.

## Themed findings by interview-guide question

The transcript reorganized against the guide. Requires the interview guide; get it if you don't have it from Phase 1.

```
## [Guide question, verbatim from the guide]

**What they said:** [synthesis in your words]

**Evidence:**
- "[quote]" — [MM:SS]
- "[quote]" — [MM:SS]

**Confidence:** [High / Medium / Low] — [why: firsthand knowledge? hedged? contradicted
themselves? based on a flagged passage?]
```

After the guide's questions, add:

```
## Raised but not asked about
[Topics the interviewee brought up unprompted. Often the most valuable section —
unprompted topics reveal what they actually care about.]

## Not covered
[Guide questions that didn't get a real answer, so the next interview can pick them up.]
```

## Newry summary card

**Check `primary-research-toolkit` for the current card format and follow that.** The toolkit owns this format and feeds it into summary cards and roll-ups; a card that doesn't match its structure creates rework at the synthesis step. Look for the synthesis or summary-card sub-skill and use its template, field names, and ordering exactly.

Only if the toolkit is unavailable, use this fallback and tell the user it's a fallback that may need reformatting:

```
# Summary Card — [Interviewee], [Company]

| | |
|---|---|
| **Project** | [name / code] |
| **Interviewee** | [name, title] |
| **Company** | [name, and its role: customer / supplier / competitor / expert] |
| **Date** | [date] |
| **Interviewer(s)** | [Newry team] |
| **Transcript** | [link or filename of the approved transcript] |

## Headline
[One sentence: the single most important thing this interview established.]

## Key findings
1. [Finding, with supporting quote and timestamp]
2. ...

## Implications for the project question
[2–3 bullets]

## Contradicts / confirms other interviews
[Where this sits against what others said, if known]

## Follow-ups
[Actions, further contacts, unanswered questions]
```
