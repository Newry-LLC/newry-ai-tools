#### S013 Development Notes (2026-05-11)
Key insights developed in session — not yet written to Stories.md:

**Earned Secrets (three, all from this session):**
1. Multi-pass pipelines are human oversight tools, not quality improvement tools — the passes create inspection points so humans can catch and fix problems, not because the model performs better in steps. Validated by the 11-of-55 source file catch.
2. The right north star metric for an AI work tool isn't time saved — it's what humans do with the time. Percentage of consultant time on judgment work vs. mechanical work before and after.
3. The tool is most valuable when it eliminates the work that prevents people from doing the work only they can do. User-validated: a senior consultant reported going from spending all week reading, coding, and synthesizing (mechanical cognitive work, high cognitive load, burnout risk) to spending that time considering the implications of findings and building strategic output.

**Before/after data strategy:**
- Can run PRT on historical projects to generate time comparison data
- Primary research workstream = ~50% of project time; tool handles ~50% of that workstream
- Frame: not just time savings — the *nature* of what consultants do changed
- Target metric: capture specific before/after from the consultant who gave feedback today (verbatim)

**Anthropic-specific angles to develop:**
1. Eval infrastructure caught 11/55 source files with invisible data problems — proof of why measurement matters
2. Multi-pass as human oversight = architectural alignment with Anthropic's safety philosophy
3. Gap analysis layer surfaces "?" for ambiguous cases rather than false confidence — honest about limitations
4. "AI handles mechanical cognitive work; human handles judgment" = working implementation of human-AI complementarity

**Status:** Story in Stories.md needs rewrite to incorporate these angles. Consultant feedback should be captured verbatim before next session.

**4th earned secret (2026-05-13 — Adam Rounick data point):**
Voluntary adoption is revealed when a colleague stops asking the expert and starts asking the tool. On 2026-05-13, Adam Rounick (Newry) invoked the plugin to find quantified outcomes from a Corning conjoint case — work that would normally require asking Sylvan directly. He asked Sylvan if they knew the quantified outcome; 24 minutes later: "Nevermind--your plugin to Claude actually did it all for me. This is awesome." He got the answer without Sylvan in the loop. That's the behavioral shift that proves the tool is working: not "users say they like it" but "the expert is no longer in the critical path." In a voluntary adoption environment where users have real alternatives (ChatGPT, native Anthropic, Notion AI), choosing to use the tool — and getting a result that eliminates the expert dependency — is the adoption signal that matters most.
